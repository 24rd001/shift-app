# シフト管理アプリ

## 概要
アルバイト先のシフト管理における課題を解決するWebアプリです。
店長とスタッフが、シフト希望提出・確認・交代申請を一元管理できます。

## 解決したい課題
- LINEや紙でのシフト連絡による情報の埋没
- 店長のシフト集計作業の負担
- スタッフ同士のシフト交代の属人化

## 主な機能
- ログイン・新規登録（スタッフ／管理者）
- シフトのタイムライン表示（本日の店舗全員＋週単位でのカレンダー確認）
- シフト希望提出
- シフト交代申請（承認フロー付き）
- 管理者によるシフト作成・確定
- 重要連絡の配信と理解度リアクション（👍理解／△あとで確認／❓質問）＋管理者向け理解度ダッシュボード
- グループ／個人トークと多言語自動翻訳（英語・中国語・ベトナム語）

## 使用技術
| カテゴリ | 技術 |
|------|------|
| フロントエンド | HTML / CSS / JavaScript |
| バックエンド | TypeScript / AWS Lambda（Node.js 20） |
| データベース | AWS DynamoDB |
| 認証 | AWS Cognito（JWT認証） |
| インフラ | AWS SAM / API Gateway |
| バージョン管理 | GitHub |

## アーキテクチャ
- サーバーレス構成（Lambda + API Gateway + DynamoDB）
- Cognitoによる認証・認可（admin/staffグループによる権限管理）
- IaC（AWS SAM）でインフラ全体をコード化

## 工夫した点
- DynamoDBのGSI（Global Secondary Index）で自分のシフトを効率的に検索
- TransactWriteItemsでシフト交代承認時の整合性を担保
- 多層防御（API Gatewayの認証 + Lambdaでのadmin判定）
- フロント・バック分業のためAPI仕様を明文化して共有

## PMの取り組み（Daiche-0624）

### 要件定義・スコープ管理
- バイト先へのヒアリングシートを作成し、課題を「業務フロー・痛み・理想」の3段階で整理
- メンバーから多数の機能提案が出た際、「ないと成立しないか」という判断軸でMVPを3機能に絞り込み
- GitHub Issuesで8つのタスクを作成し、担当・優先順位・完了条件を明確化

### チーム調整
- キックオフミーティングの資料を自作し、ゴール宣言・機能仕分け・役割分担の流れで進行
- 完成定義のズレが生じた際は即座に謝罪・再整理し、チームの混乱を最小化
- 技術的判断はエンジニアに委ね、PMは全体の方向性と進捗管理に集中

### 苦労した点
- 初学者チームのため、技術的に何が可能かを把握しながらスコープを調整するのが難しかった
- メンバーのモチベーションを維持しながら機能を削る判断が特に難しかった

### AIの活用について
- Claude AIをPM業務の補助として活用（ヒアリングシート・Issue文面・議事録整理など）
- 機能の取捨選択・チーム調整・意思決定はすべて自分で実施
- AIはあくまで作業効率化ツールとして使用し、判断は人間が行った

## バックエンド・インフラ担当の取り組み（24rd001）

### 担当範囲
- AWS環境の構築・運用（SAMによるIaC）
- Lambda関数によるAPI実装（TypeScript）
- DynamoDBのテーブル設計・GSI設計
- Cognitoによる認証・権限管理の設計
- フロント担当者とのAPI仕様共有

### 実装したAPI一覧

#### 認証系
| メソッド | パス | 機能 |
|---|---|---|
| POST | /auth/register | アカウント登録 |
| POST | /auth/login | ログイン（IDトークン発行） |

#### スタッフ向け
| メソッド | パス | 機能 |
|---|---|---|
| GET | /shifts/me | 自分のシフト一覧 |
| POST | /shifts/wish | シフト希望提出 |
| POST | /shifts/swap | シフト交代申請 |
| PUT | /swap-requests/{id}/respond | 交代申請への返答 |
| GET | /swap-requests/me | 自分宛の交代申請一覧 |

#### 管理者向け
| メソッド | パス | 機能 |
|---|---|---|
| GET | /admin/shifts | 全シフト取得 |
| POST | /admin/shifts | シフト確定 |
| GET | /admin/wishes | スタッフ希望一覧 |
| GET | /admin/swap-requests | 全交代申請取得 |
| PUT | /swap-requests/{id}/approve | 交代申請の最終承認 |

### 技術的に工夫した点
- DynamoDBのGSI設計でクエリを最適化（全件スキャンを回避）
- TransactWriteItemsで交代承認時の整合性を担保
- 多層防御（API Gateway認証 + Lambdaでのadmin判定）
- BatchGetCommandでN+1問題を回避

### 苦労した点
- CognitoのIDトークンとアクセストークンの混同による401エラー
- esbuildのバンドル出力とHandlerパスの不一致
- CORSプリフライト失敗の解消
- IAMポリシーの最小権限設計

### AIの活用について
- 設計段階：DynamoDBテーブル設計やAPI設計の壁打ち
- コーディング：概念を理解した上で自分で実装
- エラー対応：エラーメッセージを共有し原因を一緒に切り分け

## フロントエンド担当の取り組み（hide88171）

### 実装した画面一覧

#### スタッフ向け
| 画面 | 説明 |
|------|------|
| ログイン画面 | AWS Cognitoと直接連携しJWT取得・権限判定。保存アカウントから素早く切替 |
| アカウント作成画面 | 名前・メール・パスワードで新規登録 |
| ホーム | 本日の店舗全員シフトをタイムライン表示＋自分の今後の予定一覧 |
| シフト確認画面 | 週ナビ＋カレンダーから選んだ日の1週間を表示（自分の出勤日にマーカー） |
| シフト希望提出画面 | カレンダーから複数日選択して提出 |
| 交代申請画面 | 3択（代われる/無理/相談）で回答 |
| トーク画面 | グループ／個人トーク。重要連絡の理解度リアクションと多言語翻訳 |

#### 管理者向け
| 画面 | 説明 |
|------|------|
| ホーム（シフト一覧） | 全スタッフのシフトをフィルタリング表示 |
| シフト確認（週表示） | 週ナビ＋カレンダーから選んだ日の1週間を全スタッフ分まとめて確認 |
| 希望一覧 | 月別で希望表示・タップでシフト確定 |
| シフト一覧・作成 | カレンダーで絞り込み・手動作成 |
| スタッフ管理 | 管理者権限の付与・剥奪 |
| 交代申請管理 | 全申請一覧・確定/拒否ボタン（未対応件数バッジ付き） |

### UIで工夫した点
- モバイルファーストの1ファイル構成（index.html）
- ボトムナビゲーションでスマホ操作を最適化
- 本日のシフトを「横軸＝時間／縦軸＝スタッフ」のガントチャート風タイムラインで一覧化
- 重要連絡に👍理解／△あとで／❓質問の3段階リアクションを実装し、管理者側に理解度ダッシュボードと未対応者へのフォロー導線を用意
- 希望日タップでシフト確定モーダルが自動入力
- 交代申請の3択UI（相談するボタン追加）
- 1端末で管理者／スタッフを切り替えやすい保存アカウント機能
- API未実装時もlocalStorage／デモデータで動作するフォールバック設計（実APIが返れば自動で切替）

### バックエンド連携で苦労した点
- CORSエラーの解消（file://からhttp://に切り替え）
- レスポンスのキー名の違いへの対応
- ステータス管理の認識合わせ
- エンドポイントの実装状況の把握

### AIの活用について
- Claude APIをフロントから直接呼び出し多言語翻訳機能を実装
- コンソールエラーをそのまま貼り付けてデバッグを効率化
- 自然言語での要望をコードに変換する開発スタイル
